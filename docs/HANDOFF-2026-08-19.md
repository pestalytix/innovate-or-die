## Workspace drift (resolved in Phase A)

The parent workspace containing this repo also held, outside it: a loose skill copy, a `.agents/` tree symlinked to that copy, an earlier set of role prompts plus a shared `AGENTS.md`, a v1 release archive, and a standalone API-based runner. Phase A inventoried all of it against the git repo and the GitHub remote. Disposition: the loose copy proved byte-identical to the committed v1 skill and was deleted along with its symlink tree; the earlier prompts and `AGENTS.md` were copied to `docs/archive/v0-prompts/` (originals left in place — the runner loads them); the release archive and runner are out of scope and were left untouched. Archived sources: `docs/archive/`.

## Phases — hard stop at the end of each; report and wait

**Phase A — Adopt core (no generation yet).**
Verify `core/` matches this layout (9 files); report missing/divergent files instead of creating them. Inventory workspace drift per above. Move the current `skills/innovate-or-die/` content to `docs/archive/v1/` (git mv, preserve history); place a copy of the retired `innovation-mode` skill in `docs/archive/innovation-mode/` when provided. Do not generate adapters, do not modify `core/`, do not commit. List working-tree changes and stop. *Gate A: Ken approves `core/` wording and drift disposition.*

**Phase B — Build script + generation.**
Write `build/assemble.py` (stdlib-only if possible): reads `core/` + `skill-meta.json`, emits every generated tree. SKILL.md = frontmatter from skill-meta + workflow.md body with role/reference files carried alongside; flattened web variants = single file in fixed order (principles → workflow → roles → experiment spec) with a per-target character budget and a fidelity preamble ("separated passes, no context isolation"); `.agent.md` profiles = one per role file plus an orchestrator whose instructions explicitly direct the fresh-chat-per-role handoff. Within the flattened file, roles appear in execution order (innovator → critic → reviser → evaluator), and the fidelity preamble must carry `workflow.md`'s staged-loading warning explicitly — the whole file is unavoidably in context, so the preamble instructs the model to complete its innovator pass before reading the critic and evaluator sections, this being the closest available substitute for isolation.
Patch hygiene applies: idempotent, dry-run flag, and a `--check` mode that regenerates to temp and diffs against committed trees (this becomes the CI drift guard). **Verify formats against current docs at build time — do not trust manifest schemas from memory:** agentskills.io spec; code.claude.com plugin/marketplace schema (`claude plugin validate` must pass); Codex `.codex-plugin` expectations; VS/VS Code `.agent.md` frontmatter; Agent Builder instruction char limit. Record each verified fact + date in `docs/COMPATIBILITY.md`. *Gate B: `--check` clean, `claude plugin validate` passes, Ken spot-reads one generated artifact per family.*

**Phase C — Attribution + repo hygiene.**
Author fields in all manifests → Ken + kenpendergast.com. README rewrite: what it does, install matrix (one row per surface incl. "M365 Copilot: paste `adapters/web/m365-copilot-instructions.md` into Agent Builder and add `m365-copilot-knowledge.md` as a knowledge source"), the four-rung fidelity ladder (agentic hosts → Copilot agent profiles → web loader+knowledge → single-paste fallback), limitations, license. LICENSE copyright line → verify current holder, set to Ken if not already. CHANGELOG.md seeded with 2.0.0 + ADR link. *Gate C: Ken reviews README.*

**Phase D — Evals (per agentskills.io/skill-creation/evaluating-skills).**
Test cases in `evals/evals.json` per the agentskills.io schema: 5 problems, mixed domains, varied phrasing (casual + precise), at least one where the correct finding is "conventional is near-optimal." Every case runs PAIRED: with_skill and without_skill (bare prompt, same model, clean context) — the delta is the headline result. Workspace: `evals-workspace/iteration-N/` with per-case `with_skill|without_skill` dirs, `grading.json`, `timing.json` (tokens + duration), `benchmark.json`, per the reference layout. Assertions authored AFTER the first run, mechanical where possible (falsifier-with-number per opportunity, kill list >=5 entries, experiment spec complete, conventional-winner stated on the control problem); holistic quality via a blind pairwise LLM judge that does not know which arm it is scoring. Runners shell to subscription CLIs (`claude -p`, `codex exec`, Gemini CLI); pin models per MODEL_POLICY and log the RESOLVED model field per run, never the requested alias. The skill-creator skill (anthropics/skills) may drive the loop. Analysis discipline: drop assertions that pass in both arms, investigate ones that fail in both, report the with-pass/without-fail set as where the skill adds value. Results -> `evals/results/YYYY-MM-DD-<provider>-<resolved-model>.md`. Each results file must inline that iteration's `benchmark.json` numbers — the distilled results are the public record and must be self-sufficient with `evals-workspace/` gitignored. *Gate D: baseline committed; Ken reads results before any protocol tuning in response to them (tuning = new ADR + semver bump).*
